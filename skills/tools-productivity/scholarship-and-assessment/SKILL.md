# 保研与综测核验

根据适用的原始细则判断西南大学计算机与信息科学学院/软件学院学生的推免与综测成绩、加分资格和成果认定。目标是可核验的结论，不用记忆或惯例补全文件未写的规则。

## 先判定规则体系

- **推免/保研**：使用《推荐优秀本科毕业生免试攻读硕士学位研究生工作实施细则（2024级）》；综合积分 = 成绩积分 x 80% + “五育”综合评价积分 x 20%。
- **推免开源贡献补充认定**：使用《将本科生开源贡献纳入研究生推免的认定细则（计信院）》。它仅补充“五育”中的“社会服务与综合素养”，不改变成绩积分或竞赛/论文/项目表，也不适用于综测。
- **综测**：使用《本科生综合考评实施细则（2024年修订）》；基础分 = 基本素质考评 x 25% + 学业考评 x 75%，创新实践能力分 = 创新实践能力考评 x 20%。不要把这两套公式、项目表、上限或顺位规则交叉套用。
- **科研成果级别**：需要确认 T/A/B/C 级时，使用《西南大学研究项目与成果分类分级办法（试行）》；成果能否转换为推免或综测分，仍以各自细则的明确条目为准。

读取 [来源登记](references/source-registry.md) 中的文件路径。每次使用前确认文件存在、版本和适用对象；若用户提供新版、补充通知或本年度实施方案，优先读取并说明其优先级。

## 核验流程

1. 明确用户是在问推免、综测，还是两者都问；未明确时分别给出结论，不默认互通。
2. 从适用 PDF 读取相关条款、表格、备注和成果截止时间。表格须核对表头与同一行，不能仅靠文本抽取的列位置。
3. 对每项成果核对赛事/成果名称、级别、奖项、团队人数与顺位、作者/发明人排序、第一署名或专利权人、正式发表/授权/检索状态和取得日期。
4. 只在所有必要条件被材料证明时给出确定分值。计算时展示公式、原始分、权重、四舍五入规则，并标注尚未证实的假设。
5. 给出简短的原文依据（条款或表格页）和源文件引用。多层级/同一赛事获奖、封顶、限项、不可累加等备注必须一并检查。

## 开源贡献（仅推免）

开源贡献与主推免细则共同适用。每项经认定的独立贡献为 0.2 分，学生的开源贡献累计上限为 1 分（最多 5 项）；还须同时检查主细则“社会服务与综合素养”类别的总体上限。贡献须在当届推免工作开始前产生，不得重复申报，并须公开可查、可追溯。

- **A 类核心代码**：累计至少 2 个经社区审查、正式合并且关联 Issue 或功能描述的 PR/MR；核对合并链接、审查记录和仓库主页。
- **B 类项目创建与主导**：项目文档完整、有实际价值、明确开源协议；考评期内至少 5 次提交，且 Star 至少 20 或 Fork 至少 6；核对项目、指标截图和当年提交记录。
- **C 类社区运营与知识推广**：在知名项目长期担任 Issue Triager 或文档维护等角色，并处理至少 10 个 Issue，或完成至少 5 次重要文档修订；核对角色与处理记录。
- **D 类活动组织**：作为主要负责人，经校院审批成功组织一场院级及以上开源技术分享、工作坊或沙龙；核对策划、负责人名单和宣传总结。

每类的“至少”条件只是最低门槛，仍由学院推免工作小组审核真实性、合规性和材料完整性。发现弄虚作假，取消当年全部开源贡献加分。

## 防止臆测的硬约束

- 文件未列出成果、主办方或对应关系不清时，结论写为“现有细则无法确认/通常不计分，待学院认定”，不得自行类推到相近赛事。
- “录用”“拟收录”“送检”“参会”“往届可检索”不等于正式发表、授权或 EI Compendex 全文收录。按细则要求正式成果和可核验材料。
- 不为代写、买作者位、伪造证书、挂名或规避审核提供建议；说明其不能作为真实成果申报。
- 对“保证”“包录用”“包检索”等第三方宣传，只解释其不能替代学院认定，不承诺最终计分。
- 不要把“北大中文核心”“CSCD”“EI全文”“CCF B/C”等名称自动等同；先查科研分类文件与推免/综测的专门映射。

## 回答格式

先给明确结论（可计分/不可计分/待核验），再给分值或公式及必要条件。若用户只问一个项目，回答保持简洁；若计算多个项目，使用小表格。始终标注“推免”或“综测”，避免用户将两个分数混淆。
